# MTG Dashboard — State of the Project Review

## What this is
Personal SQLite + Streamlit dashboard replacing an Excel/Office 365-based MTG collection and deck tracker. Tracks a personal card collection, 20+ Commander decks, maybeboards, game history, and analytical views. Playgroup includes Joe G, Anthony, and Joe M, whose decks appear in game logs but aren't fully tracked in the system.

## Status: fully built and tested (within sandbox constraints — see caveat at bottom)

Migration/data-layer foundation is complete and validated. The Streamlit dashboard is built out across **5 pages**, all backed by a shared library, all writable directly (no CSV editing required for day-to-day use anymore).

**Phase 1 refactor applied:** the Retired Decks concept (`is_active`/`successor_deck_id`) was removed entirely — every tracked deck is now assumed active. The standalone Tag Editor page was folded into the Editor page as a new "Card Tags" tab, and the separate "Deck Tags" feature (the `deck_tags` table) was removed outright — deck-level notes live in the description/combos/tutors fields instead. The Editor's Card Data "Refresh" action now also automatically prunes the collection (see below). Databases built before this change keep their old `is_active`/`successor_deck_id`/`deck_tags` columns physically in place (nothing is destructively dropped from a live SQLite file); `ensure_schema()` just normalizes the data (every deck → active, no successor) on connect, and the app code no longer reads or writes any of it.

**Phase 2 (Editor/Collection enhancements + new Commander Game Tracker) applied:** Date Acquired now uses a real calendar date picker (defaults to today when adding a lot). Deck Themes moved from free text to a dropdown backed by a master `theme_catalog` table you manage directly (add/remove entries in an Editor expander); removing an entry only changes what the dropdown offers, never touches a deck's existing assignments. Game Changers got the same treatment on the category side (`game_changer_category_catalog`) plus a brand-new Editor tab showing every Game Changer card (Scryfall-flagged or custom-tagged) with art, editable categories, owned quantity, and how many decks currently run it. Collection got Showcase/Borderless filter+columns (`cards.is_showcase`/`is_borderless`, populated from Scryfall's `frame_effects`/`border_color` at fetch and refresh time, with an MDFC front-face fallback). Decks got an optional custom cover-image thumbnail (`decks.cover_image_path`, a user-uploaded PNG saved under `image_cache/deck_covers/`), the Image Grid default bumped from 24 to 48 cards/page, an editable Win Conditions/Strengths/Weaknesses section in Deck Info (these tables already existed in the schema but had no write path before), and Top 10 Most Expensive / Top 10 Saltiest card panels. Salt scores (`cards.edhrec_salt`) are a new hand-maintained field — Scryfall's API doesn't expose EDHREC salt, so this is edited directly in the Editor's Card Data tab and deliberately never touched by the Scryfall refresh action. Finally, a whole new **Commander Game Tracking** page: log a game (up to 4 seats, each a tracked deck via dropdown or free text for an opponent, with an optional player name and win flag per seat, plus notes), an actual rendered game history (not a raw table) with a way to delete a mis-entered log, and win-rate comparisons by deck (existing `deck_stats` view) and by player (new `player_stats` view, `game_participants.player_name` column — only populated for games logged from now on).

**Phase 3 (Mana Curve & Color Breakdown, MDFC awareness, Weighted Mana Graph, Commander Cast Probability, Mana Text Rule Parser) applied:** Cards with a Land face on EITHER side of a Modal Double-Faced Card (e.g. `type_line` "Instant // Land") are now recognized as lands everywhere it matters — mana-curve exclusion, the Land Probability page's land count, and every color-source calculation — via a new MDFC-aware `is_land` column (`formatting.has_land_face()`, wired into `card_view.add_derived_columns()`), replacing the old front-face-only `card_type == "Land"` check used for these specific purposes (the existing `card_type` bucket itself is unchanged, still front-face-only, still used for display elsewhere). Decks & Maybeboard's Mana Curve chart is now non-land-card-only (MDFC-aware) and stacked/itemized by either Card Color or Card Type (a toggle), built directly from the already-loaded deck dataframe rather than a flat SQL count — the old `queries.deck_mana_curve()`/`loaders.load_deck_mana_curve()` are left in place (additive policy) but no longer called from the page. A new keyword/text rule parser (`formatting.classify_mana_colors()`) reads a card's own oracle text to classify what it can produce — "any color" phrasing (Command Tower, City of Brass, Exotic Orchard, Birds of Paradise, ...) is flagged as an Any-Color source even though those cards' own `color_identity` field is empty (no colored symbols in their text), a bare `{C}` with nothing else (Access Tunnel) is Colorless, plain colored symbols set specific colors, and anything unparseable falls back to the `color_identity` field. `formatting.is_mana_rock_or_dork()` uses the same text parsing to flag nonland Artifacts/Creatures with a mana ability. The Land Probability page's existing color-source counting (`probability.count_color_sources()`) now uses this parser instead of trusting `color_identity` alone, fixing the any-color-land gap in both the lands-only and "include nonland" modes. Two new engines were added to that page: a **weighted mana-source availability graph** (`probability.mana_source_category_counts()` + `weighted_mana_expectation()`) — turn-by-turn EXPECTED count (not "at least one" probability) of sources in each of Rocks/Dorks, Colorless, Any Color, and each WUBRG color, via hypergeometric linearity of expectation — and a **Commander Cast Probability engine** (`probability.parse_colored_pips()` + `commander_cast_probability_by_turn()`), Turn 1–10, compounding the land-drop probability (enough lands drawn for the commander's mana value) with the color-source probability (enough sources of each colored pip in its cost) as independent factors; looks up the commander/partner's own card row via a new `queries.cards_by_name()` since the commander lives in the command zone, not the shuffled library. Hybrid/Phyrexian pips (`{U/B}`, `{U/P}`) are deliberately excluded from the color requirement rather than counted toward every color they mention, since they can be paid another way. The "Check a specific card" tool now excludes pure lands (`formatting.is_pure_land()` — a card whose type line is Land on every face) per spec, while still listing land-having MDFCs since their other face is a real card to check for. **No schema/migration changes were needed** — `cards.oracle_text` already existed and was already populated by the Scryfall fetch path; Phase 3 is Python-logic-only.

`dashboard_lib` is deliberately split: everything with "no Streamlit dep" above is pure `sqlite3`/stdlib and was unit-tested standalone; `db.py`/`loaders.py`/`card_view.py` hold the Streamlit caching and shared UI widgets.

## Critical philosophy shift: migration is now one-way

`migrate.py` wipes and rebuilds `mtg_collection.db` from the CSVs **every time it runs**, with zero attempt to preserve anything edited in the dashboard since. This was explicitly requested — an earlier version had a complex tag-preservation backup/restore mechanism that was deliberately ripped out and simplified.

**The rule: run `migrate.py` once for initial CSV import, then never again.** All ongoing management (card tags, deck metadata, mainboard/maybeboard, themes, collection, Game Changer categories, salt scores, game log) happens in the dashboard from then on.

Because of this, schema changes can no longer ride in on a re-migration. `queries.ensure_schema()` (called automatically inside `get_connection()`) applies additive, non-destructive upgrades on every connect: `ALTER TABLE` for new columns, `CREATE TABLE`/`CREATE VIEW` for new tables/views. This is how `cards.is_reserved` reached existing databases in Phase 1, and how the Phase 2 additions (`is_showcase`/`is_borderless`/`edhrec_salt`/`cover_image_path`/`player_name`, plus the `theme_catalog`/`game_changer_category_catalog` tables and `player_stats` view) reached them too. **Important nuance caught during Phase 2 testing:** a brand-new install via `migrate.py` builds straight from `schema.sql`, so `theme_catalog`/`game_changer_category_catalog` already exist (empty) before `ensure_schema()` ever runs its "seed on first creation" logic — which only fires for *upgrading* a pre-Phase-2 database that doesn't have the table yet. `migrate.py` itself was updated to seed both catalogs directly (right after loading `deck_themes`/`game_changer_tags` from their CSVs), so fresh installs and upgraded databases both end up with a populated dropdown. Confirmed by re-running the project's own offline migration test against the real CSVs — 39 themes / 6 categories seeded correctly.

## The 5 pages, in brief

1. **Collection** — table/grid toggle (image grid defaults to 48/page as of Phase 2), layered filters (color, type, rarity, set, location, foil, basic land, Game Changer, Reserved List, Showcase, Borderless, price, mana value), multi-level group-by breakouts, Scryfall links from both views.
2. **Decks & Maybeboard** — Turn 0 panel (commander/partner/colors/bracket/interaction/combos/tutors/win-loss/value/sleeved-count/optional cover-image thumbnail), win conditions/strengths/weaknesses, themes, mana curve (Phase 3: MDFC-aware non-land-only, stacked by Color or Type), type breakdown, strategy tag breakdown, optimized-mana summary, Game Changers table (drift vs. Scryfall highlighted), Reserved List table, Top 10 Most Expensive / Top 10 Saltiest panels, in-panel Moxfield export (copy-to-clipboard code box + save-to-file), and the same card browser scoped to Mainboard/Maybeboard/Both.
3. **Land & Color Probability** — hypergeometric math per deck: land-drop odds per turn, opening-hand distribution, color-source availability per turn per color (Phase 3: text-parser-based, any-color lands correctly counted), a Phase 3 weighted mana-source-availability graph (Rocks/Dorks, Colorless, Any Color, per-WUBRG-color expected counts turn-by-turn), a Phase 3 Commander Cast Probability engine (Turn 1–10, compounding land-drop and color-source odds), and a lookup for any specific card's odds (Phase 3: excludes pure lands). Auto-detects library size/land count excluding the commander, MDFC-aware.
4. **Editor** — deck rename (with optional `collection.location` cascade)/metadata/create/**delete** (cascades correctly, detaches rather than deletes historical `game_participants` rows, requires typing the exact name to confirm); a cover-image uploader and Win Conditions/Strengths/Weaknesses editor, both new in Phase 2; themes add/remove via a master-catalog dropdown (Phase 2); **Card Tags** (moved from the old standalone Tag Editor page) — bulk-edit any tag_type across a whole deck's mainboard in one table; mainboard/maybeboard add (with live Scryfall resolution for brand-new cards)/bulk-edit/remove; collection add (real date picker, Phase 2)/bulk-edit/remove; **Game Changers tab** (new in Phase 2) — every Scryfall-flagged or custom-tagged card across the whole database with art, editable categories from a master catalog, owned quantity, and how many decks run it; **Card Data tab** — refreshes Reserved List/Game Changer/Showcase/Borderless/legality/price for every existing card by its permanent Scryfall ID with a progress bar, then automatically prunes the collection (see below), plus a Salt Scores sub-editor (Phase 2, hand-maintained, never auto-refreshed).
5. **Commander Game Tracking** (new in Phase 2) — log a game (up to 4 seats, each a tracked deck via dropdown or free text for an opponent's deck, optional player name + win flag per seat, plus notes); rendered game history with a delete option for corrections; win-rate comparisons by deck and by player.

## Data/schema facts worth remembering

- **`decks.color_identity` is concatenated letters** (`"RB"`), **not** comma-separated like `cards.color_identity` (`"B,R"`) — different parser needed for each (`fmt.deck_color_identity_letters` vs. `fmt.color_identity_display`). This was a real bug found and fixed mid-project.
- The commander card itself **is** a row in `deck_cards` (100 total = 99 + commander). Probability calculations subtract the commander/partner to get the true shuffled-library size. Phase 3's Commander Cast Probability engine looks the commander/partner's own card row back up by name (`queries.cards_by_name()`) since it needs their `mana_cost`/`cmc`, which the shuffled-library dataframe doesn't include (it's excluded from that dataframe on purpose).
- **MDFC land awareness (Phase 3):** `formatting.has_land_face(type_line)` checks BOTH faces of a card (split on `" // "`) for "Land" — this is distinct from `formatting.derive_card_type()`, which still only looks at the front face for display bucketing. `card_view.add_derived_columns()` adds this as a new `is_land` column used by the mana curve, Land Probability page, and color-source counting; the older `card_type == "Land"` check is still used elsewhere for display purposes where front-face bucketing is what's wanted.
- **Mana-source color classification (Phase 3):** `formatting.classify_mana_colors(type_line, oracle_text, color_identity)` is the keyword/text rule parser — "any color" phrasing in a card's own oracle text wins over its `color_identity` field (fixes Command Tower/City of Brass/Exotic Orchard, whose `color_identity` is empty), a bare `{C}` with nothing else is Colorless (Access Tunnel), plain colored symbols set specific colors, and `color_identity` is only the fallback for text this regex-based parser can't read. Hybrid/Phyrexian pips (`{U/B}`, `{U/P}`) in a mana COST (as opposed to a mana ability) are deliberately excluded from `probability.parse_colored_pips()`'s color-requirement count for the same "can be paid another way" reasoning.
- `card_tags` is deck-scoped: PK is `(deck_id, scryfall_id, tag_id)`. There is no deck-level tags table anymore — that was removed in Phase 1.
- `cards.is_game_changer`, `cards.is_reserved`, `cards.is_showcase`, and `cards.is_borderless` are all pulled from Scryfall's live fields **at fetch time only** — they don't silently stay current. The Editor's Card Data tab / `refresh_card_data.py` is how you resync them later. `is_showcase` comes from `frame_effects` containing `"showcase"` (falls back to the front face's `frame_effects` for MDFCs, since the top-level list can be empty on those); `is_borderless` comes from `border_color == "borderless"`.
- `cards.edhrec_salt` is a **hand-maintained** field, unlike the four above — EDHREC salt scores aren't exposed by the Scryfall API at all, so there's nothing to auto-fetch. It's edited per-card in the Editor's Card Data tab (search by name) and deliberately excluded from the refresh action's UPDATE statement. Powers the Decks & Maybeboard "Top 10 Saltiest" panel; cards with no score recorded are excluded from that panel rather than shown as zero.
- `game_changer_tags` (custom sub-categories: Combo/Mana/Power/Stax-Unfun/Tutor/Value) is separate from `is_game_changer`. As of Phase 2 it has an in-dashboard editor (Editor → Game Changers tab), card-name-keyed (not deck-scoped) same as the table itself; the set of valid category names lives in a new `game_changer_category_catalog` table you manage separately (add/remove doesn't touch existing tag assignments). `mana_tags` remains CSV-only with no in-dashboard editor yet.
- **Theme dropdown (Phase 2):** `theme_catalog` is a new master list (`theme` TEXT PRIMARY KEY) that the Editor's Themes tab dropdown reads from — separate from `deck_themes` (the actual per-deck main/sub assignments, unchanged). Seeded once, either by `ensure_schema()` on an upgraded pre-Phase-2 database or by `migrate.py` on a fresh install, from whatever distinct theme names already exist in `deck_themes`.
- **Deck cover image (Phase 2):** `decks.cover_image_path` stores a path relative to `BASE_DIR`, same convention as `cards.local_image_path` — e.g. `image_cache/deck_covers/12.png`. Uploaded PNGs are written straight to that path from the Editor; no resizing/validation beyond the file-type filter.
- **Player names in game logs (Phase 2):** `game_participants.player_name` is new and nullable — historical rows imported by `migrate.py` from `games_played.csv` don't have one (the CSV baked player names into the opponent's deck-name string instead, e.g. `"Aesi, Tyrant of Gyre Strait (Anthony)"`, which is left as-is). Only games logged through the new Commander Game Tracking page populate this column, and the "win rate by player" view (`player_stats`) only reflects those.
- Deleting a deck clears its mainboard/maybeboard/card tags/themes/win-strengths-weaknesses, detaches (not deletes) its `game_participants` rows so other players' results in shared games survive, and optionally clears matching `collection.location` text.
- **Collection pruning** (`writes.prune_collection()`) runs automatically as part of the Card Data "Refresh" action: any collection lot with no assigned location, a quantity of 0/none, and not present in any deck's mainboard or maybeboard is deleted.
- Two deck names — Rakdos Showstopper and Vorevold, Sac Master — predate `deck_mapping.csv` and are registered directly in `migrate.py` (`FORMER_DECK_NAMES`) purely so their entries in `games_played.csv` link to a real `deck_id` rather than falling through to the free-text "unmatched opponent" path.

## Known open items / not built

- **Proxy flag** on the Turn 0 panel — blocked on confirming the Location/Proxy convention with you (never resolved).
- HTML/CSS print-to-PDF one-pager.
- EDHREC comparison — explicitly deprioritized as a full comparison view. Note this is narrower than the salt-score field added in Phase 2, which is just a hand-entered per-card number, not a live EDHREC integration.
- A "browse the full official Game Changers list" discovery view (owned vs. not-yet-owned) — the Phase 2 Game Changers tab only shows cards already in your database (owned, or run in a deck), not WotC's full official list irrespective of ownership.
- Rule 0 tags still have no dedicated data source — the Card Tags tab supports a "rule0" tag_type like any other, but nothing populates it automatically yet.
- Mana tags (`mana_tags.csv` / `mana_tags` table) still have no in-dashboard editor, unlike Game Changer categories which got one in Phase 2 — same CSV-only status as before.
- No delete/edit for individual `deck_win_conditions`/`strengths`/`weaknesses` rows beyond full-list replace — `writes.set_deck_rank_list()` always replaces the whole ranked list for a deck+kind at once rather than patching a single rank in place. Fine for the current 3-rank-max UI, but worth knowing if this ever needs finer-grained editing.

## Testing approach (important caveat)

No live Streamlit or network access exists in the build sandbox. Everything was validated via: a hand-built `streamlit` stub module simulating widgets/caching, an offline mocked-Scryfall migration harness for realistic test data, unit tests for every `dashboard_lib` write function against scratch SQLite databases, and full regressions after every change.

Phase 2 specifically added: a test that builds a synthetic pre-Phase-2-shaped database and runs `ensure_schema()` against it, confirming every new column/table/view appears, the two catalogs seed correctly from pre-existing `deck_themes`/`game_changer_tags` data, and a second `ensure_schema()` call is idempotent and doesn't clobber catalog edits made in between; direct unit tests for every new `writes.py`/`queries.py` function (theme/category catalog CRUD, game-changer tag assignment, salt scores, deck cover image, rank-list replace semantics, `create_game`/`delete_game`, the price/salt top-10 and win-rate queries); unit tests for `scryfall_lookup.to_card_row()`'s new Showcase/Borderless parsing (plain card, showcase-only, borderless-only, both, MDFC front-face fallback, and fields missing entirely); an end-to-end mocked `refresh_all_cards()` run confirming the new flags actually get written; and — importantly — a full re-run of the project's own real `_test_migrate_offline.py` harness against your actual CSVs (not synthetic data) to catch the fresh-install catalog-seeding gap described above before it shipped.

**None of this has been run against real Streamlit or real network access** — first actual use (launching the real dashboard, clicking through the new tabs and the new page, running a real Card Data refresh against live Scryfall) is the real-world validation still outstanding.

**Phase 3 testing specifically:** an offline script exercises `formatting.has_land_face()`/`is_pure_land()`/`classify_mana_colors()`/`is_mana_rock_or_dork()` against realistic card text for every example named in the spec (Command Tower, City of Brass, Exotic Orchard, Access Tunnel, a plain dual, a basic, Birds of Paradise, Sol Ring, plus an MDFC land and negative cases), then builds a synthetic enriched library dataframe (30 lands across basics/any-color/colorless/dual/MDFC-land-face, plus rocks/dorks/spells) to check `probability.count_color_sources()`, `mana_source_category_counts()`, `weighted_mana_expectation()`, `parse_colored_pips()` (including hybrid-pip exclusion), and `commander_cast_probability_by_turn()` (monotonicity, factor multiplication, colorless-commander edge case) all against hand-computed expected totals. Beyond that, the Streamlit stub was extended (columns/tabs/expander/selectbox/radio/toggle/number_input/slider/column_config, etc. — all now return deterministic defaults instead of `None`) so that **every page script, including the two touched by Phase 3, was actually executed end-to-end** against a from-scratch synthetic `mtg_collection.db` (a real 5-color-ish Commander deck built with `hashlib`-based deterministic card IDs, matching the project's established offline-test convention) rather than only import-checked — confirming no page raises, and (via a print-capturing variant of the same run) spot-checking the actual numbers each section would render: land-drop/color-availability tables, the weighted-source table, the commander cast-probability curve, the stacked mana-curve pivot, and the pure-land-excluded card checker all matched hand-calculated expectations for that synthetic deck.
